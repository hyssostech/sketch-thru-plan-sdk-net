notes, and the detailed changelog - are the single source of truth in
[src/StpSDK.JsonRpc/Docs/ReleaseNotes.md](src/StpSDK.JsonRpc/Docs/ReleaseNotes.md),

## 0.6.1
- **Fixes `OnNewScenario`, `OnInkProcessed` and `OnSpeechDiscarded` never firing against a real engine (STP-1067).** The engine sends a payload-less event with the `params` key absent altogether, and the dispatcher returned early on a missing `params` before it reached them. The tests fed `"params": {}`, a shape the engine never sends. Payload-less events now fire with `params` absent, null or `{}`; an event that needs a payload and arrives without one is reported through `OnStpMessage` instead of vanishing
- **Fixes every `ObjectSet` request being refused (STP-1067).** `LoadNewScenarioAsync`, `ImportSTPDataAsync`, `SyncScenarioSessionAsync`, `ImportTaskOrgAsync` and `ImportCoaAsync` taking an `ObjectSet` sent it serialised to a string under `content`; the engine reads an `objects` array, as the public contract and the JS SDK say, so it saw no objects and failed. They now send `objects`
- **Fixes `GetCoaContentAsync` and `GetTaskOrgContentAsync` throwing on every real answer (STP-1092).** The engine answers with STP object-set text (`object_set([...])`), and both ran `JToken.Parse` on it. They now return that text unchanged as `Task<string>` (was `Task<object>`), which is what `ImportCoaContentAsync` / `ImportTaskOrgContentAsync` take back. The unit tests had fed JSON, a shape the engine never sends; they now use the contract's captured text, and a live smoke test round-trips both
- **Added `SetCoaTaskOrgAsync(toPoid, coaPoid)` and `ResetCoaTaskOrgAsync(affiliation, coaPoid)`** for the contract's `SetCoaTaskOrg` / `ResetCoaTaskOrg`. Without a `coaPoid` they act like `SetDefaultTaskOrgAsync` / `ResetDefaultTaskOrgAsync`; engines before STP-1077 refuse a `coaPoid`
- **Fixes `HasActiveScenarioAsync` always returning false, and `ImportSTPDataAsync` reporting success on a false answer (STP-1093).** The engine answers with a JSON boolean, which reaches these methods as `"True"`/`"False"`; they compared case-sensitively with `"true"`/`"false"`. The tests had fed the lower-case strings the connector never produces
- **Added `TaskWhat.HARASSMENT_FIRES`**, the corrected spelling the engine emits since STP-1019. Without it a harassment-fires task arrived as `NOT_SPECIFIED`. It is appended at the end of the enum, so existing ordinals are unchanged; `HARRASSMENT_FIRES` is `[Obsolete]`
- **Added `StpSDK.Validation.StpCallValidations`, the shared call-validation rules evaluated around a state-changing call (STP-1064).** Before the call, `Validate(method, params, context)` refuses it, with the reason and the fix, when the method has no rules, a param the engine silently ignores the call without is missing, the session has no active scenario, or a poid names no existing object of the right kind; a destructive method comes back with the confirmation text to show the user. After it, `Watch`/`Diff` match the events that arrived against what the call asked for and report `Done`, `Partial`, `NotDone`, `Other`, `Unknown` or `Unverifiable` with a one-line summary. The rules are the sdk-js `json-api/sketch-thru-plan-validations.json`, the file the stp-mcp live server evaluates too, embedded as a verbatim copy pinned to a commit (`StpCallValidations.Pin`); the same parity cases run through both evaluators
- **Added `StpSDK.Search.SymbolSearch`, the contract's `SearchSymbol` (STP-1373).** It lists the symbols whose spoken phrases match a typed text, best first, from a symbol index the SDK loads (`SymbolIndex.Load(path)`, format `stp.symbol-index.v1`) - no engine round trip. The ranking is STP's own symbol search (passes exact, prefix, stem, stem prefix, edits; a classic tf-idf score; word-by-word merge), with one change by ruling: an entry whose phrase is exactly the text ranks first. Measured against STP's recorded golden queries, it gives STP's top result first in 97.8% of them (99.2% counting the exact-phrase rule) and within the top five in all. The index ships with STP, not here: `SymbolIndex.LoadDefault()` finds it - a path given, else `STP_SYMBOL_INDEX`, else the highest STP version installed under Program Files (Desktop before Server) - and a missing one is a `SymbolIndexUnavailableException` naming every path tried. The contract's conformance cases run as tests, from a pinned copy
- **Task values the engine no longer produces are `[Obsolete]`**: `TaskWhat.DEMONSTRATING`, `LOOTING`, `RIOTING`, `SEEK_REFUGE` and `TaskHow.CIVILIAN` (STP-1001), `TaskHow.INSURGENT` and `NGO_OPERATION` (STP-1019). They still parse, so older engines and saved data keep working; they go in the next major release
- **STP 5.12 support: contract 0.9.11 (STP-1797, STP-1798, STP-1799).** Task history: `GetTaskHistoryAsync`, `AddTaskCommentAsync`, `EditTaskCommentAsync`, `DeleteTaskCommentAsync` and the `OnTaskEventAdded` / `OnTaskEventModified` events. Batches: `OnBatchStarted` / `OnBatchEnded`, and the trailing `batchId` of the 18 object events through additive `On<Event>Ext` events (existing delegates are unchanged). Call params now match the contract: `SetCurrentCoa` sends `poid` (was `coaPoid`), `ChooseAlternate` sends `nBestIndex` (was `nbestIndex`). Also new: `SetRoleAsync(role, createIfNone)`, `StpRecognizer.User` (sent on `Register`), typed `StpC2SIMOptions` (including `RefuseUnconfirmedPlaceholders`), `StpRole` constants (including `ENGINEER`), per-call `TimeSpan` timeouts on the object-set loads with the engine's report in `StpObjectSetLoadException`, and `PullC2SIMInitializationContentAsync`, which returns the contract's XML string. The contract is vendored and pinned, and a coverage test maps each of its methods and events to an SDK member
- **Fixes `ImportSTPDataAsync` returning false on success (STP-1799).** The contract answers null on success; all three overloads now return true for it. A refusal still throws
- **Behavior change: `SwitchRoleAndCoaAsync` / `SwitchRoleAndCoa` (STP-1799).** `SwitchRoleAndCoa` is not a contract method and no engine dispatches it. They now send `SetRole` with `role`, then `SetCurrentCoa` with `poid`; a null or blank `coaPoid` sends `SetRole` only. The async form throws if either call is refused, and does not send `SetCurrentCoa` when `SetRole` is refused
- **`[Obsolete]` (STP-1803)**: `CreateCoaAsync`, `GetCurrentCoaPoidAsync`, `CreateDefaultCoaAsync`, `RequestActiveCoasAsync` (`GetActiveCoaList`), `GetScenarioCoasAsync` (`GetScenarioCoaList`) and `GetCoaObjectsAsync` send methods the contract does not have, and the STP bridge refuses them; `GetCoaObjectsAsync` points to `GetCoaObjectSetAsync`. The tuple-returning `PullC2SIMInitializationAsync` points to `PullC2SIMInitializationContentAsync`. `SwitchTaskConfirmationAsync` stays obsolete in favour of `ConfirmTask`
- **COAs are not supported in STP 5.12 (STP-1803).** The COA calls and events (`AddCoa`, `UpdateCoa`, `DeleteCoa`, `SetCoaAsync`, `GetCoaContentAsync`, `ImportCoaContentAsync`, `GetCoaObjectSetAsync`, `ImportCoaAsync`, `SetCoaTaskOrgAsync`, `ResetCoaTaskOrgAsync`, `SwitchRoleAndCoa(Async)`, `OnCoaAdded` / `Modified` / `Deleted`) stay in the SDK, and their documentation says so. The COA sample is removed
- **Naming: "batches" (STP-1803).** The docs, samples and comments call the STP-1265 `BatchStarted` ... `BatchEnded` groups "batches", not "change sets"; the engine uses "change set" for something else. No type, member or wire name changes
- Samples (STP-1802): task history and comments (TaskingSample), object set loads with a timeout and batches (ScenarioSample), task org object sets (TaskOrgSample), symbol search (EditingSample), typed C2SIM options (C2SIMSample), `StpRole.All` role lists; `samples/PARITY.md` lists every contract method and event with the JS and .NET samples that show it

## 0.6.0
- **BREAKING (platform): the SDK now targets .NET 10.** .NET 8 leaves support on 2026-11-10. `netstandard2.0` is unchanged, so .NET Framework consumers are unaffected, and a consumer still on .NET 8 resolves the netstandard2.0 asset rather than breaking
- **Fixes events vanishing when the engine sends a symbology value this build does not know.** Degrading gracefully was the entire purpose of the converter involved, and it did the opposite - the enclosing event was dropped in silence. Engine and SDK version independently, so this is an ordinary deployment condition rather than an edge case
- **Fixes `ConnectAsync` ignoring both its cancellation token and its retry timeout.** Connecting to an unreachable engine hung the caller indefinitely, with no error and no diagnostic; a 30-second token was measured still blocked after 240 seconds
- **A dispatch handler that discards an engine message now says so.** 22 of the 35 handlers returned early on an unexpected payload and not one of them reported it, which is how a real defect looked exactly like the engine never sending the event. They now report through `OnStpMessage` at Warning level, naming the event and the missing field
- **Added `StpSymbol.CompositeSvg(width, height)`**, which composes symbol layers as SVG with no imaging library involved, so the cross-platform path no longer depends on `System.Drawing`. `Bitmap()` is untouched and still ships
- **Every dependency is now pinned to an exact version in one place.** `System.Drawing.Common` had been a floating `5.*` range, which resolves differently over time with no commit and no review. Several majors advanced in the process and these flow to consumers transitively
- **The samples, quickstart and plugins are built and analysed in CI for the first time**, along with the .NET Framework sample that is the only consumer of the netstandard2.0 target - a leg that until now shipped untested
- **Test coverage is measured for the first time.** The collector had been a dependency of the test project for a long time and was invoked by nothing, so every run resolved it and measured zero
- **The release path is verifiable end to end**: actions are SHA-pinned and enforced, the dependency audit is proven able to fail, an SBOM is produced and scanned, publish credentials no longer share a job with third-party install code, and the tag, the packed version and the registry must all agree before anything is pushed
- **API documentation publishes again**, and the package version, changelog and release notes can no longer drift apart without CI saying so

## 0.5.0
- **Fixes `OnSpeechParsed` never firing.** The handler read a `parsedAlternates` field, but the bridge sends the alternates under `alternates` (`StpJsonClient.cs`), so the event was silently dropped on every recognition
- Added `RefreshSubscriptionsAsync`, so a handler attached after connect is routed instead of staying silently unsubscribed; when it cannot refresh, it now names the real cause
- Samples: every sample and plugin project was unbuildable in Release - the StpSDK reference sat in a Debug-only `ItemGroup` - and the samples called a dead method instead of `ConfirmTask`
- **A refused request now carries a readable message.** STP answers a method it cannot dispatch with `success:false` and a null result; that arrives as a `JToken` of type Null, not a C# null, so the `?? "Request failed"` fallback never fired and `ToString()` on it returned the empty string. Every refusal surfaced as an `StpException` with an EMPTY message, which is how a family of undispatched methods stayed invisible. The engine text is used when present, otherwise an explanatory sentence pointing at the engine log
- **Fixes `GetScenarioObjectSetContentAsync`, `GetTaskOrgObjectSetAsync`, `GetCoaObjectSetAsync` always throwing**: the engine answers these with a bare array of objects, not `{"objects":[...]}`; the SDK now accepts both. The old unit-test oracle had encoded the wrong shape, so the suite was green while every live call failed
- Added `ConfirmTask`, `SendSimulatedSpeechRecognition`, `ConvertC2SIMContentAsync` to close the DISPATCHED wire-surface gap with the JS SDK (all three have engine dispatch arms; `ConvertC2SIMContent` currently returns null - the engine has not implemented conversion, so a null result does not mean failure)
- **BREAKING (behavior)**: `SendSimulatedSpeechRecognition(string, DateTime?)` now sends the engine's dedicated `SendSimulatedSpeechRecognition` wire method (server-side number/letter-to-word conversion), matching the JS SDK, instead of a client-side stand-in that wrapped the raw text as a single `SendSpeechRecognition` recoList item. The client-side stand-in called this SDK's own `ConvertToTranscription`, which despite its name passes text through verbatim, so typed input reached STP unconverted while the JS SDK got the phonetic form - `"A 3 1"` stayed `"A 3 1"` instead of becoming `"alpha three one"`. `ConvertToTranscription` stays public but is no longer used by any path here, and its doc now says plainly that it does not transcribe
- `SwitchTaskConfirmationAsync` marked `[Obsolete]`: its wire method `SwitchTaskConfirmation` has no case arm in the engine's dispatcher on any release line and silently does nothing; use the new `ConfirmTask` instead
